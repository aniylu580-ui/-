# 开发路线图（Roadmap）

> 开发顺序按用户指定的 5 步执行；每个阶段有明确验收标准，验收通过才进入下一阶段。

## 阶段 0：项目文档初始化（当前，已完成）

- 目标：建立 AGENTS.md + docs 全套文档，让任何新对话/AI 不"犯病"
- 交付物：AGENTS.md、README.md、docs/PRODUCT_SPEC.md、docs/ARCHITECTURE.md、docs/DATA_MODEL.md、docs/IMPORT_AND_CLASSIFICATION.md、docs/ROADMAP.md、.gitignore 更新
- 验收：文档一致性自查通过；"新 AI 考卷"5 问可答；UTF-8 无乱码

## 阶段 1：前端展示页

- 目标：可直观展示数据的网页骨架
- 任务：官方脚手架创建 frontend/（Vue3 + TS + Vite + Pinia + Element Plus）；基础布局（顶栏/侧栏）；仪表盘占位；交易列表页；类目管理页；后端最小骨架（FastAPI + PostgreSQL + Alembic 建表）
- 验收：`npm run dev` 可打开页面；后端 `/healthz` 正常；交易列表能展示后端返回的模拟数据

## 阶段 2：微信/支付宝账单导入与识别展示

- 目标：上传账单 → 解析 → 标准化 → 前端以 UI 风格展示"抄出来的数据"
- 任务：导入模块（解析、去重、批次）、上传界面、解析结果展示（含统计与失败行）
- 验收：真实微信账单（zip/CSV）与支付宝账单（CSV）各一份能正确导入；重复导入被拒绝；金额/时间/方向准确

## 阶段 3：记一笔 + 查找

- 目标：手动记账与检索
- 任务：记一笔表单（收入/支出/转账、类目、商户、时间、备注）、编辑/删除、列表筛选搜索（时间/商户/类目/金额/备注）
- 验收：手动记录可查可改可删；搜索组合条件正确

## 阶段 4：数据处理核心

- 目标：自动归类 + 对账（同笔资金识别）
- 任务：分类流水线（规则 → 记事谱 → AI → 人工确认弹窗）；记事谱管理界面；匹配模块（退款/当天还/AA）与确认/撤销
- 验收："李掌柜烧饼店"类场景自动归餐食；"利克"首次弹窗确认、二次直接命中；退款/当天还/AA 提议正确且可确认撤销；统计口径正确（AA 净支出、退款不重复计）

## 阶段 5：报表

- 目标：周/月/自定义时间段报表
- 任务：报表聚合服务（类目汇总、账户汇总、趋势）；报表页面（表格 + 图表）；口径与交易明细一致
- 验收：任意时间段报表金额与明细核对一致；排除退款与已确认往来冲销；图表可读

## 后续（不在当前 5 阶段内）

- PWA/原生 App、多用户、付费/充值、多币种、导出 CSV、预算管理、安全测试专项
