# 账单导入与自动分类（核心功能说明书）

## 1. 微信/支付宝账单导出与格式

- 微信：微信支付 → 钱包 → 账单 → 下载账单（按日期范围），得到 zip，内含 CSV（GBK 编码，字段间逗号分隔，表头前有说明行）
- 支付宝：支付宝 App → 我的 → 账单 → 开具交易流水证明 / 导出账单，得到 CSV（UTF-8 或 GBK，视版本）
- 通用处理：zip 解包 → 探测编码（优先 UTF-8，失败按 GBK）→ 跳过说明行 → 定位表头行 → 按字段映射表解析

### 字段映射（微信常见表头）

| 微信表头 | 标准字段 |
|----------|----------|
| 交易时间 | occurred_at |
| 交易类型 | txn_type 判定依据（"商户消费""退款""转账"等） |
| 交易对方 | raw_payee |
| 商品 | note（备注） |
| 收/支 | direction |
| 金额(元) | amount（转 amount_cents） |
| 支付方式 | account 判定 |
| 当前状态 | status（只导入"支付成功/已全额退款"等有效状态） |
| 交易单号 | platform_txn_id |
| 商户单号 | merchant_txn_id |
| 备注 | note（合并） |

- 支付宝表头类似（交易号、商家订单号、交易对方、商品名称、金额、收/支、交易状态、时间等），映射到同一标准字段
- 表头容错：忽略大小写/空格/括号差异；找不到必填字段时报错并提示用户
- 金额处理：字符串转整数分（保留两位小数；处理"¥"、负号、千分位）；"收入/支出"以收/支列或金额正负判定

## 2. 导入流程

1. 上传文件 → 计算 SHA-256 → 若 `import_batches` 已存在相同 `file_hash` 且成功 → 拒绝并提示
2. 解包/解析 → 生成标准交易数据
3. 去重：与库内交易比对去重键（platform + platform_txn_id + merchant_txn_id + amount_cents + occurred_at）；同一批次内重复也去重
4. 落库：创建 import_batch + transactions（status=pending，classification_source=unclassified）
5. 触发分类流水线（见下）
6. 前端展示解析结果（交易列表 + 导入统计：总数/成功/重复/失败）

## 3. 分类流水线（三层 + 人工兜底）

对每条待分类交易：

```text
1) 归一化商户名
   - 去首尾空格、全角转半角、统一大小写
   - 去除常见行业后缀噪音（如"有限公司/店/餐饮"）生成 name_normalized
2) 记事谱精确命中（user_confirmed 条目）
   - 命中 → 直接用其 category_id；classification_source=merchant_memory
   - 不调 AI；结束
3) 确定性规则
   - 关键词规则：如"烧饼/餐/食/美团外卖"→餐食；"地铁/滴滴/打车/加油"→交通；
     "淘宝/京东/拼多多"→购物；"房租/电费/水费"→居住 等（规则库可配置）
   - 交易类型规则：微信/支付宝标记为"退款"→ 进入对账处理，类目沿用原交易
   - 规则命中且置信度高（如唯一命中）→ 归类；classification_source=rule
4) AI 兜底（可配置开关；默认开）
   - 触发条件：规则未命中，或规则与记事谱冲突
   - 只发送：name_normalized、金额、时间、txn_type、备注（脱敏）
   - 要求返回 JSON：{ category_id | category_name, confidence, reason }
   - 类目选项必须来自用户当前类目列表（AI 不得发明类目）
5) 人工确认
   - 触发条件：AI confidence < 0.8，或规则与 AI 冲突，或 AI 不可用
   - 弹窗列出候选类目供用户选择
   - 用户确认 → 写回记事谱（source=user_confirmed，覆盖旧条目）；classification_source=manual
6) 反馈闭环
   - 用户任何手动纠错（编辑分类）都写回记事谱
   - 记事谱命中次数 match_count+1，越用越准；AI 调用随记事谱增长而减少
```

关于"AI 是否需要逐笔复核"：不需要。规则高置信命中即结束；AI 只在低置信/冲突时兜底，控制成本、延迟与隐私暴露。

示例：

- "李掌柜烧饼店" 15 元 → 记事谱无记录 → 规则命中"烧饼→餐食" → 归类餐食（若用户纠正，则写回记事谱）
- "利克"（便利店）→ 规则拿不准 → AI 低置信 → 弹窗 → 用户选便利店 → 写回记事谱；下次直接命中，不再调 AI

## 4. 同笔资金识别（对账）

只对 status=pending 且未被分类到"往来冲销"的交易做匹配；系统只生成"提议"，用户确认后才改变统计口径。

### 4.1 退款

- 条件：同一用户、同一商户（name_normalized 相同，或相似度 ≥ 0.9）、金额相等、方向相反（支出 vs 收入）、occurred_at 差 ≤ 7 天（可配置）、且收入交易 txn_type/备注含退款特征
- 处理：确认后组为 match_type=refund；统计时退款不重复计入支出

### 4.2 借款当天还

- 条件：同商户、金额相等、方向相反、occurred_at 差 ≤ 24 小时、无消费特征（如对方为个人转账）
- 处理：确认后组为 match_type=repay_same_day；双方标记为"往来冲销"，不进入消费报表

### 4.3 AA 分账

- 条件：一笔支出（金额 X）与一笔收入（金额 Y），Y < X，对方不同名或为个人，occurred_at 差 ≤ 3 天（可配置），且未被其他规则匹配
- 处理：确认后组为 match_type=aa_split；净支出 = X − Y，报表按净支出统计（例：结账 300、朋友转 200 → 支出 100）
- 注意：Y 可能不是同一朋友；由用户确认"是否同一顿饭"。宁可漏提议，不要错误合并

### 4.4 匹配的通用原则

- 一切匹配都是"提议"，用户确认后生效；可撤销（撤销后恢复原统计口径）
- 匹配日志写入 audit_logs；匹配理由（reason）展示给用户

## 5. AI 网关（可插拔）

- 接口抽象：`classify(merchant, amount_cents, occurred_at, txn_type, note, categories) -> ClassificationResult`
- 默认实现：OpenAI 兼容 Chat Completions（`base_url`、`api_key` 走环境变量），可切换 DeepSeek/通义千问/本地模型
- 隐私：只传最少必要字段；请求/响应日志脱敏；开关 `AI_CLASSIFICATION_ENABLED`（默认 true，可关）
- 降级：AI 超时/失败/关闭 → 直接进入人工确认队列，不影响导入主流程
- 提示词约束：必须从给定类目列表中选择；禁止编造类目；返回 JSON；低置信时必须返回低 confidence

## 6. 边界与失败场景

- 空文件/损坏 zip/编码探测失败 → import_batch 标记 failed，前端显示错误原因
- 表头缺失必填列 → 拒绝导入并提示缺哪列
- 金额解析失败（如非数字）→ 该行进失败列表，不中断整批
- 同一文件重复上传 → file_hash 命中，拒绝并提示
- AI 不可用 → 所有未分类交易进入人工确认队列
- 用户删除某笔交易 → 相关联的对账组若只剩一条则转为 rejected 或提示用户
