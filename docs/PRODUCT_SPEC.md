# 产品需求说明书（Product Spec）

## 1. 背景与目标用户

目标用户：希望"不用每笔记账也能知道钱花在哪"的个人用户。

核心场景：月底想复盘支出，但懒得逐笔记录；微信/支付宝账单能导出，却看不出钱去哪了，也分不清退款、借款当天还、朋友 AA 转账和真实消费。

## 2. 痛点

1. 逐笔手动记账太累，坚持不下去
2. 月底看到"花了很多钱"但不知道花在哪
3. 账单里混着退款、借款当天还、AA 转账，容易重复统计或误判（例如：结账 300 元，朋友转回 200 元，真实消费只有 100 元）
4. 微信/支付宝账单文件格式不同，手工整理费时

## 3. 功能需求（P0 = 核心必做，P1 = 后续增强）

### P0：随手记

- 手动记录一笔收入/支出/转账：金额、类目、商户/对方、时间（默认当前时间，可改）、备注
- 验收：保存后出现在交易列表；金额与时间准确；可编辑、可删除

### P0：自定义类目

- 系统提供默认类目（餐食、交通、购物、居住、娱乐、医疗、转账往来、其他），用户可增删改
- 验收：新建类目后即可用于记一笔和自动分类

### P0：账单导入（微信/支付宝）

- 上传微信/支付宝导出的账单文件（支持 zip 内的 CSV 与直接 CSV）
- 自动解析为标准化交易数据并以符合前端 UI 风格的界面展示
- 自动去重，重复导入不产生重复数据
- 验收：见 `docs/IMPORT_AND_CLASSIFICATION.md` 的解析与去重规则

### P0：自动分类

- 按"规则 → 记事谱 → AI → 人工确认"流水线给每笔交易归类
- 用户确认/纠错的分类写回记事谱
- 验收：分类结果可追溯来源与置信度；用户确认过的不被自动覆盖

### P0：同笔资金识别（对账）

- 自动提议退款、借款当天还、AA 分账；用户确认后生效，可撤销
- 确认后的统计口径：退款不重复计支出；AA 按"净支出"统计（结账 300、收款 200 → 支出 100）
- 验收：见 `docs/IMPORT_AND_CLASSIFICATION.md` 的匹配规则

### P0：查找

- 按时间范围、商户、类目、金额、备注关键字过滤/搜索交易
- 验收：任一条件组合可查询，结果含分页

### P0：报表

- 周报、月报、自定义时间段报表；按类目汇总、按账户汇总、每日/趋势图
- 验收：报表金额与交易明细一致；口径排除退款与已确认的往来冲销

### P1：记事谱管理界面

- 查看/编辑/删除"商户名 → 类目"的记忆条目
- 验收：编辑后立即影响后续分类

### P1：更多增强

- 导出报表 CSV、多币种、多用户、付费/充值（均列入后续阶段，见"v1 不做"）

## 4. 核心业务规则（简版，详见专项文档）

- 金额以"分"为整数存储；时间按 UTC 存储、界面按本地时区显示
- 分类流水线：归一化商户名 → 记事谱精确命中（直接归类，不调 AI）→ 规则 → AI 兜底 → 低置信度（< 0.8）或冲突时人工确认 → 确认结果写回记事谱
- 同笔资金：退款（同商户/等额/反向/7 天窗口）、当天还（等额/反向/对方相同/24 小时窗口）、AA 分账（收入 < 原支出/对方不同/3 天窗口）；系统只提议，用户确认后生效

## 5. v1 明确不做

- 多用户/多人协作（数据模型预留 user_id）
- 付费、充值、订阅
- 多币种（默认 CNY）
- 原生手机 App（先做响应式网页 + PWA，复用同一 API）
- 银行、信用卡账单导入（后续可扩展，导入接口按平台插件设计）
